ABSTRACT
BikeMS is a comprehensive web-based Bike Rental and Management System developed using the Laravel PHP framework. The primary objective of the system is to digitize and stream- line the workflow of bike rental agencies while providing an intuitive, seamless reservation experience for customers.
The system features robust authentication, personalized client dashboards, and modular interfaces for Administrators, Staff, and Customers. Customers can browse available bikes, view dynamic pricing plans, and make online reservations. To enhance the user experience, BikeMS integrates an advanced tracking simulation using the Leaflet Routing Machine and OSRM (Open Source Routing Machine) API, allowing users to visually track their rented bike’s delivery route in real-time.
Furthermore, the platform incorporates a Sentiment Analysis and Review module. Cus- tomers can leave emoji-based feedback after unlocking a bike, and administrators have access to detailed sentiment reports via graphical charts and Excel exports. By combining an elegant Tailwind CSS-driven user interface with powerful back-end features, BikeMS ensures efficient inventory management, transparent pricing, and improved customer satisfaction in the bike rental domain.

INTRODUCTION
The advent of the internet has significantly revolutionized how typical businesses operate, open- ing the pathway for online services spanning a multitude of domains. Bike rentals represent a crucial part of the modern urban mobility ecosystem, providing an eco-friendly, cost-effective, and practical solution for commuting and tourism. Traditionally, renting a bike required manual paperwork, phone calls, and physical visits to agencies to check availability.
The ”BikeMS” project aims to modernize this workflow through a full-stack, comprehen- sive web application built with the robust PHP framework, Laravel. It provides a cohesive online platform tailored to solve the inconveniences of conventional bike renting. The platform bridges the gap between administrators, operational staff, and customers.
Through BikeMS, customers can effortlessly browse inventory, select bikes categorized by type, and reserve them using flexible pricing tiers (Hourly, Daily, Weekly). This eliminates the friction associated with verifying bike availability. Moreover, the project introduces real-time engagement features such as the integration of tracking simulation using the Leaflet API and OSRM demo servers. This innovative touch allows customers to visualize the location and route of a dispatched bike.
To bridge consumer feedback into actionable metrics, the system also features an Emoji- based Sentiment Analysis module. Customers can express their satisfaction through intuitive emoji choices, and the backend aggregates this data to present graphical reports and Excel data exports for the administration.
Ultimately, BikeMS simplifies inventory tracking for admins while offering an interactive and reliable user experience for the customers.
SUPPORTING LITERATURE
Overview
The study of existing systems highlights several operational gaps in traditional bike rental and transportation workflows. Many current solutions manage reservations via isolated spread- sheets lacking a unified customer-facing portal, or they possess monolithic web architectures without interactive features.
Review of Technologies
Laravel Framework: Known for its elegant syntax and MVC architecture, Laravel has proven to be an excellent backend choice for dynamic web applications. Its Eloquent ORM enables robust database manipulation.
Tailwind CSS: A utility-first CSS framework that allows rapid UI creation without leav- ing the HTML (or Blade) structure. It ensures the application is fully responsive out-of- the-box.
Leaflet routing machine: Open-source JavaScript libraries map rendering and routing. By leveraging OpenStreetMap data and the OSRM backend network, Leaflet allows com- plex route visualization and delivery simulation, enriching the user experience signifi- cantly.
Proposed Enhancements
While basic CRUD (Create, Read, Update, Delete) applications suffice for simple renting op- erations, BikeMS includes modern analytical elements such as Sentiment Reporting. A dash- board that aggregates customer reviews using visual emojis directly maps qualitative reviews into quantitative metrics for management analysis.
SYSTEM ANALYSIS
Module Description
The ”BikeMS” project is divided into distinct functional modules catering to the specific needs of administrators, operational staff, and customers.
Authentication & Authorization: Handles secure login, registration, and password re- covery. It distinguishes users according to their roles (Admin, Staff, Customer), routing them to appropriately permitted dashboard areas upon login.
Inventory & Bike Management: Administrators and staff can perform CRUD opera- tions on bike entries. Features include uploading bike pictures, setting rental prices, and tracking current availability status.
Booking & Reservation: Allows end-users to view active pricing plans securely, pick dates for rental, and confirm bookings. It automatically alters the status of the bike in the registry to prevent double-booking.
Customer Verification: Requires customers to upload a valid DL (Driving License) image for verification before unlocking and renting a bike, maintaining safety protocols.
Review & Sentiment Analysis: After completing a rental or during unlocking, cus- tomers can rate the service using emojis. Background processes score and tally these reviews, presenting a Sentiment Analysis graph on the admin dashboard with the option to export the sentiment report via Excel.
Tracking Simulation Module: Customers can open a real-time tracking interface show- ing a simulation of a delivery driver or the bike routing to a destination. Powered by Leaflet Routing Machine and an OSRM backend, it visually interpolates map coordi- nates to mimic active movement.
Business Rules
Security & Access: Users must be registered and authenticated to book a bike. Staff cannot access administrative configurations.
Rentals: A single user may rent multiple bikes, but a single bike cannot hold concurrent reservations on overlapping dates.
Verification: A booking cannot activate into an ”in-use” status without proper approval and DL image submission.
Review Limitations: Only users with an active or completed booking log can submit a review. Sentiments are constrained to specific emoji selections mapped to internal ratings (e.g., Happy, Neutral, Sad).

SYSTEM DESIGN
Architecture Overview
The project follows the standard Model-View-Controller (MVC) architectural pattern enforced by the Laravel framework.
Model: Eloquent classes mapping to PostgreSQL database tables (Bike, User, Booking, Review).
View: Blade template files structuring the UI, powered by Tailwind CSS.
Controller: PHP scripts receiving HTTP requests, interacting with Models, and passing data down to the Views.
Database Design
The system architecture includes several interconnected schemas utilizing Foreign Keys for referential integrity.
Users Table: Stores authentication details and roles.
Bikes Table: Contains attributes such as model name, registration plate, status, and im- age paths.
Bookings Table: Links a User ID to a Bike ID, documenting timestamps, status, and attached documents (like DL images).
Reviews Table: Links a User ID to predefined sentiment ratings corresponding to an emoji.
User Interface Design
An emphasis was placed on creating an immersive, clean, and responsive interface.
Customer Interface
The customer dashboard features dynamic views outlining active plans, recent bookings, and a dedicated interface to track route simulations. It relies on crisp typography, generous whites- pace (rounded image containers with soft shadows), and interactive hover elements.

TESTING
Testing is a cornerstone of software development, ensuring system reliability, performance, and usability. Given the complex nature of a full-stack platform like BikeMS, an extensive testing strategy was implemented.
Unit Testing
Unit tests verify individual components in isolation.
Model Testing: Validated the Bike, User, and Booking Eloquent models to ensure relationships, foreign keys, and accessors work as intended.
Controller Testing: Routes like the Customer Booking form and Staff Dashboard up- dates were tested for valid HTTP response codes (e.g., 200 OK, 302 Redirect).
Integration Testing
Integration testing evaluates how different modules interact.
Database Integration: Assessed if creating a Booking properly checks the availability status of a Bike before committing the transaction.
API Integration (OSRM): Simulated responses from the external OSRM demo server to guarantee the Tracking Module fails gracefully with an intuitive error message in case of API timeouts.
User Acceptance and UI Testing
The front end, designed with Tailwind CSS, was tested across multiple viewports (Mobile, Tablet, Desktop) to ensure the interface dynamically scales without breaking elements. Manual tests included the user flow of logging in, selecting a bike, uploading a dummy DL image, and checking the real-time tracker.
DEPLOYMENT
Deployment involves hosting the project on an accessible server for production usage.
Local Deployment
During development, the generic php artisan serve command provides a robust local- ized server environment. Using standalone PHP bundled with PostgreSQL satisfies backend prerequisites.
Steps involved:
Clone the repository using Git.
Run composer install to fetch PHP dependencies.
Configure the .env file with the respective PostgreSQL credentials.
Run php artisan migrate and php artisan db:seed to generate and pop- ulate schemas.
Execute npm install and npm run build (or dev) to compile Tailwind CSS as- sets.
Production Deployment
For full public deployment, standard VPS or Managed Hosting solutions (such as Forge or cPanel-based environments) support Laravel and PostgreSQL. Utilizing an SSL certificate guar- antees HTTPS security, maintaining encryption for login endpoints and preventing sensitive data (DL uploads) interception.
GIT HISTORY
Git serves as the core version control system for BikeMS, facilitating parallel development, backtracking, and feature iteration without damaging the main stabilizing branch.
Commit Practices
Semantic commit messages (e.g., feat: add sentiment export, fix: resolve map timeout) were utilized to ensure an organized timeline. Commits were chunked based on the modification of specific modules rather than sweeping undocumented changes.
Branching Strategy
Development spanned across multiple feature branches, enabling isolated sandboxing for risky features such as the integration of the Leaflet Routing Machine. Upon stability checks, these individual branches were merged back onto the main timeline.
CONCLUSION
The BikeMS platform successfully modernizes the traditional model of bike renting through the synergy of web technologies. Employing the MVC structure of Laravel ensured code maintain- ability, security, and scalability. Customer friction is drastically minimized via instantaneous booking capabilities and dynamic pricing plans.
Additionally, by capitalizing on advanced sentiment reporting and visual map route sim- ulations powered by Leaflet, BikeMS is elevated from a barebones CRUD platform into an engaging web application that provides substantial analytical value to its administrators. It stands as a comprehensive solution ready to accommodate the evolving demands of urban bike rentals.
